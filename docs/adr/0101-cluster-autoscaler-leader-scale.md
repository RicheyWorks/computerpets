# 0101. The scheduled Cluster Autoscaler leader scales the underfilled zone

- **Status:** Accepted (the per-zone max is [0104](0104-per-zone-node-max.md); the per-zone floor is [0106](0106-api-single-zone-hostname-floor.md); a Pending pod never holds the lease, [0110](0110-cluster-autoscaler-pending-lease.md))
- **Date:** 2026-09-23
- **Code:** `deploy/k8s/cluster-autoscaler.yaml`; `deploy/terraform/modules/node_pool/main.tf`; `deploy/k8s/check-cluster-autoscaler-leader-scale.sh`

## Context

[0100](0100-api-hostname-hard-spread.md) left this gap: a Pending Cluster Autoscaler standby does not hold the lease, so it does not raise desired capacity, while the scheduled replica still can. Inventory on `main` tip `95ba2aeb1` (cluster-autoscaler v1.36.1):

|---------|-------------|--------------------|
| Container command | `--leader-elect=true` on the `leases` lock named `cluster-autoscaler`. `--namespace=kube-system`. `--node-group-auto-discovery` on the two discovery tags. `--balance-similar-node-groups=true`. `--expander=least-waste`. `--skip-nodes-with-system-pods=false` | No check that a wrong expander, a bare or true `skip-nodes-with-system-pods`, a scheduler allow-list, or a single `--nodes` group can regress. The v1.36.1 default for balance is false. The default for `skip-nodes-with-system-pods` is true. The default expander is already `least-waste`, and deleting the arg would hide that pin |
| Node groups | One managed group per subnet, at least two zones, `min_size` 1, `max_size` 10, the same `instance_types` list, the same `computerpets/node-pool=api` label, the same `NoSchedule` taint. One subnet per group, so the Auto Scaling group has one availability zone | Not recorded as the groups the leader scales when hard zone spread leaves the second pod Pending |
| IRSA | `eks:DescribeNodegroup` is a describe action. `autoscaling:SetDesiredCapacity` is tag-scoped | Not tied to the template the leader simulates |
| Zone item ([0099](0099-cluster-autoscaler-zone-hard-spread.md)) | `DoNotSchedule`, `maxSkew` 1, Honor policies, `minDomains` unset. Replicas 2. Required hostname anti-affinity. The file is out of the kustomization | Unchanged by this slice |

v1.36.1 starts the scale loop only on the replica that holds the lease. A Pending pod does not hold it. The standby is not the scaler. Unschedulable Deployment pods in `kube-system` are scale-up candidates. DaemonSet pods are not. This workload is a Deployment. `--namespace` is the namespace where the process runs the lease and the status ConfigMap. It is not a pod filter. `--skip-nodes-with-system-pods` is scale-down: true (the binary default) waits before deleting a node that runs a non-DaemonSet kube-system pod. It does not drop Pending kube-system pods from scale-up. `--allowed-scheduler-names`, when set, keeps only pods that name a listed scheduler. It is unset. `--nodes` is unset, so discovery is the only group list.

The AWS provider builds the scale-up template from the Auto Scaling group. `topology.kubernetes.io/zone` is that group's first availability zone. One subnet per group makes that zone the group's zone. `eks:DescribeNodegroup` copies the node group's label and taint onto the template, so `computerpets/node-pool=api` and the `NoSchedule` taint are present. The pending pod's `nodeSelector` and toleration match. Hard zone spread then accepts a new node only in the zone that keeps skew at 1. The crowded zone's template fails the predicate, so it is not an expansion option for this pod. `--balance-similar-node-groups` balances only groups that can schedule the same pods. It does not move this pod's scale-up onto the crowded zone. `--expander=least-waste` chooses among options that pass the predicate. `random`, `most-pods`, `price`, `priority`, and `grpc` are not used. A comma chain is not used. Ties after a chain are broken at random, which can strand one AZ when pods fit every zone. Identical groups share one instance-type list, so least-waste does not prefer one zone's type, and similar-group balance keeps those sizes together.

## Decision

**The standby is not the scaler. The scheduled leader raises desired capacity on the underfilled zone's Auto Scaling group. The command keeps `--balance-similar-node-groups=true`, `--expander=least-waste`, and `--skip-nodes-with-system-pods=false`. `--namespace=kube-system` stays the lease namespace and is not a pod filter. There is no `--allowed-scheduler-names` and no `--nodes` list. Node groups stay one similar group per zone, at least two, with discovery tags on every group. Kind and minikube do not apply this file.**

1. **Who scales.** `replicas` stay 2. `--leader-elect=true` stays, on the `leases` lock named `cluster-autoscaler`. Only that holder calls `SetDesiredCapacity`. A Pending replica does not hold the lease. The standby is not the scaler. The leader does not have to run in the underfilled zone. Discovery tags and the tag-scoped allow cover every zone's group.
2. **Flags that keep the path.** `--balance-similar-node-groups=true` is set. The v1.36.1 default is false. `--expander=least-waste` is the only expander argument. `random`, `most-pods`, `price`, `priority`, `grpc`, and a comma chain are refused. `--skip-nodes-with-system-pods=false` is set. The v1.36.1 default is true. A bare `--skip-nodes-with-system-pods` is true. It is refused. The flag does not filter Pending pods. `--namespace=kube-system` stays. It is not a pod filter. `--allowed-scheduler-names` is not set. `--nodes` is not set. Auto-discovery on the two tags stays the group list.
3. **Groups the leader can grow.** At least two zones. One managed node group per subnet. `subnet_ids` is that one subnet, so the template zone is the group's zone. Every group uses `var.instance_types`, the label `computerpets/node-pool=api`, and the `NoSchedule` taint. Discovery tags are `setproduct` of every zone and both tag keys. `min_size` stays 1. `max_size` is 20 ([0104](0104-per-zone-node-max.md)), above the floor, and at least the HPA ceiling. A single-AZ floor, one group that lists every subnet, a per-zone instance-type split, or tags on one zone only are refused. There is no raw `aws_autoscaling_group`.
4. **Why the underfilled zone is the option.** The template carries `topology.kubernetes.io/zone` from the group's availability zone and the pool label and taint from `eks:DescribeNodegroup`. That describe action stays allowed and is not on the deny list. Hard spread (`DoNotSchedule`, `maxSkew` 1, Honor, `minDomains` unset) makes a new node in the crowded zone fail the predicate. The underfilled zone's new node keeps skew at 1 when that zone has room on the new node. Similar-group balance does not redirect this pod onto a group that cannot schedule it.
5. **What this slice does not change.** The zone item stays. Replicas stay 2. Required hostname anti-affinity stays. Required zone anti-affinity is not set. `minDomains` stays unset. Do not set minDomains. The pool selector and the taint toleration stay. `minAvailable` stays 1. The image stays `registry.k8s.io/autoscaling/cluster-autoscaler:v1.36.1`. The file stays out of the kustomization. HPA stays min 3 / max 10. The API PDB stays `minAvailable: 2`. The kube-proxy reassert hook stays [0097](0097-kube-proxy-toleration-hook.md). No live AWS apply.
6. **Kind and minikube.** This file stays out of the kustomization. `kubectl apply -k deploy/k8s` does not install it. `enable_node_pool=false` does not plan the groups or the role. Kind and minikube do not apply this file. Do not add it to make a laptop scale. Do not set `minDomains`. Do not add required zone anti-affinity. Do not taint a kind or minikube node.
7. **Verify without a cluster.** `check-cluster-autoscaler-leader-scale.sh` fails when balance is missing or not `true`, when the expander is not exactly `least-waste`, when `skip-nodes-with-system-pods` is missing, bare, or `true`, when `--namespace` is not `kube-system`, when `--allowed-scheduler-names` or `--nodes` is set, when leader election is off, when the zone floor drops below two, when a group takes every subnet, when instance types are not the shared list, when discovery tags are not the product of every zone, when `max_size` is not 20 ([0104](0104-per-zone-node-max.md)), when `eks:DescribeNodegroup` drops off the describe list, when `minDomains` is set, when required zone anti-affinity appears, or when `kustomization.yaml` lists the file. `check-cluster-autoscaler-leader-scale.test.sh` proves those regressions. No `kubectl apply` and no `terraform apply`.

## Consequences

- The standby is not the scaler. A Pending Cluster Autoscaler pod does not call `SetDesiredCapacity`. The scheduled leader does, including for the Auto Scaling group in the zone that would fit that Pending pod.
- On two or more zones, hard spread still refuses the crowded zone. The leader's simulation refuses it too. The new node is requested in the zone that keeps skew at 1, while that group's desired size is below its max ([0104](0104-per-zone-node-max.md)).
- `--balance-similar-node-groups=true` still balances pods that fit every similar group, so one AZ is not the only group that grows for those pods. It does not pull the topology-constrained standby onto the crowded zone.
- `--skip-nodes-with-system-pods=false` still lets scale-down consider a node that runs this Deployment, subject to `minAvailable: 1`. It does not ignore the Pending pod.
- Kind and minikube do not apply this file. One labeled zone still schedules both pods when two hostnames exist. A node that omits `topology.kubernetes.io/zone` leaves both pods Pending. Do not set `minDomains`. Required zone anti-affinity is not set.
- The one-group-per-loop wait is [0102](0102-cluster-autoscaler-scale-up-salvo.md). A zone already at max 10 cannot grow. A failed scale-up backs that group off before the next try. Those waits are not a second scaler.
- The kube-proxy managed addon schema still rejects `tolerations`. Coverage between applies depends on the [0097](0097-kube-proxy-toleration-hook.md) hook and on the flag being true.
- Dropping the balance flag, switching the expander, restoring `skip-nodes-with-system-pods`, adding a scheduler allow-list or a `--nodes` list, or collapsing the groups to one AZ fails `check-cluster-autoscaler-leader-scale.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.
