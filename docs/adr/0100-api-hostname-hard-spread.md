`ScheduleAnyway` scores a less-loaded hostname and still binds when the score cannot be met. On a pool that already has two eligible hostnames, that still allows 2 and 0 for the local blue count, and 3 and 0 for the HPA floor. `minDomains: 2` is the wrong lever: with one eligible domain it treats the global minimum as 0, so the second pod's skew is 2 and the pod stays Pending. Kind and minikube would then fail even after a human labels the one node. Required hostname anti-affinity is also the wrong lever: it skips the second pod whenever every eligible node shares one hostname, including the local blue count of 2. The zone item already uses `DoNotSchedule` without `minDomains`. The hostname item follows that shape.

## Decision

**The hostname `topologySpreadConstraints` item on `computerpets-blue` and `computerpets-green` sets `whenUnsatisfiable: DoNotSchedule`. `maxSkew` stays 1. `nodeAffinityPolicy` stays `Honor`. `nodeTaintsPolicy` stays `Honor`. `minDomains` stays unset. The zone item stays `DoNotSchedule`. One hostname still schedules. A node that omits `kubernetes.io/hostname` does not. Required hostname anti-affinity is not set.**

1. **Hostname item.** Both colors. `topologyKey` is `kubernetes.io/hostname`. `maxSkew: 1`. `whenUnsatisfiable: DoNotSchedule`. `nodeTaintsPolicy: Honor`. `nodeAffinityPolicy: Honor`. `labelSelector.matchLabels` stays `app: computerpets` plus that Deployment's own color. Green pods do not count toward blue's skew. There is one hostname item per color. `matchLabelKeys` is not set.
2. **No minDomains.** Unset minDomains behaves as 1. Do not set minDomains. A floor of 2 would treat a single hostname as an empty second domain and leave the second pod Pending. That is the laptop failure this slice refuses.
3. **What hard spread does.** Eligible domains are hostnames of nodes that match the pool selector, that this pod can tolerate, and that carry `kubernetes.io/hostname`. The skew is the count in the candidate hostname, plus one, minus the smallest count among those domains. `maxSkew: 1` refuses a larger difference. On two or more such hostnames that can take a pod, the live color cannot place every pod on one node. On two hostnames the local blue count of 2 is 1 and 1, not 2 and 0. On two hostnames the HPA floor of 3 is 2 and 1, not 3 and 0. Pods of one color can still share a node when the pod count exceeds the hostname count by at most that skew. If the lighter hostname has no remaining capacity, the pod stays Pending. Cluster Autoscaler can add a node. This slice does not change the scaler.
4. **One hostname still schedules.** When every eligible node shares one hostname, there is one domain. The skew of adding a pod there is 1, which `maxSkew: 1` allows. Hard spread does not invent a second node. Kind and minikube with one eligible hostname still run both local blue replicas on that node, once the node also carries `computerpets/node-pool=api` and one `topology.kubernetes.io/zone` value. The second pod is not left Pending by this hostname item. Required hostname anti-affinity would leave that second pod Pending. It is not set. A node loss that removes the other hostname's nodes leaves one domain, and the remaining hostname can take every pod.
5. **Missing hostname label.** `DoNotSchedule` skips a node that does not have `kubernetes.io/hostname`. The kubelet sets that label. A node that omits it does not receive an API pod.
6. **Zone stays hard.** The zone item stays `maxSkew: 1`, `DoNotSchedule`, `nodeTaintsPolicy: Honor`, `nodeAffinityPolicy: Honor`, with `minDomains` unset. One labeled zone still schedules. Required zone anti-affinity is not set.
7. **What this slice does not change.** HPA stays min 3 / max 10. The API PDB stays `minAvailable: 2`. Both stay out of the kustomization. Local replicas stay blue 2 / green 0. The pool selector and the `NoSchedule` toleration stay. Postgres and Redis stay unpinned and unconstrained. metrics-server zone spread is [0098](0098-metrics-server-zone-hard-spread.md). Cluster Autoscaler zone spread is [0099](0099-cluster-autoscaler-zone-hard-spread.md). A Pending Cluster Autoscaler standby does not hold the lease. The scheduled replica still can raise desired capacity. That note is not this slice. The kube-proxy reassert hook stays [0097](0097-kube-proxy-toleration-hook.md). No live AWS apply.
8. **Kind and minikube.** These Deployments are in the kustomization, so `kubectl apply -k deploy/k8s` installs the hard hostname item. Their nodes omit `computerpets/node-pool=api` unless a human labels one, and they omit `topology.kubernetes.io/zone` unless a human sets one value. Both labels are required before the API schedules. One eligible hostname still schedules both blue replicas. The second pod is not left Pending by this item. Do not set `minDomains`. Do not add required hostname anti-affinity. Do not taint a kind or minikube node. `enable_node_pool=false` does not add either label and does not remove the constraint.
9. **Verify without a cluster.** `check-api-hostname-hard-spread.sh` fails when either color's hostname item is not `DoNotSchedule`, when `maxSkew` is not 1, when `nodeAffinityPolicy` or `nodeTaintsPolicy` is not `Honor`, when `minDomains` or `matchLabelKeys` is set, when a required hostname anti-affinity term appears, when the zone item is not `DoNotSchedule`, when the pool selector or the taint toleration drops, or when the HPA floor, the HPA ceiling, or the API PDB `minAvailable` drifts. `check-api-hostname-hard-spread.test.sh` proves a soft blue hostname item, a soft green hostname item, `nodeAffinityPolicy: Ignore`, a dropped taint policy, `minDomains: 2`, `maxSkew: 2`, `matchLabelKeys`, a required hostname anti-affinity, a soft zone item, a dropped HPA floor, a dropped API PDB, and a dropped pool key. No `kubectl apply` and no `terraform apply`.

## Consequences

- On a pool whose nodes span two or more eligible hostnames and can take a pod, the live color cannot place every pod on one node. `maxSkew: 1` and `DoNotSchedule` refuse the crowded hostname.
- One hostname still schedules. A kind or minikube node that carries `computerpets/node-pool=api` and one `topology.kubernetes.io/zone` value still runs both blue replicas. The second pod is not left Pending by this item. Hard spread is not a second node. Required hostname anti-affinity would leave that second pod Pending. It is not set.
- `minDomains` stays unset. Setting it to 2 would leave the second pod Pending on one hostname. Do not set it.
- When the lighter hostname cannot fit the pod, the pod stays Pending instead of joining the crowded hostname. That wait is the cost of hard spread. Cluster Autoscaler is what adds the node. This slice does not apply it. A Pending Cluster Autoscaler standby does not hold the lease, so it does not raise desired capacity for the group that would fit the pod. The replica that is already scheduled still can.
- Pods of one color can still share a node when the count stays inside `maxSkew`. On two hostnames the HPA floor of 3 is 2 and 1. A crash of the node that holds two is involuntary. The PDB does not apply.
- A hostname that loses every eligible node stops being a domain. The remaining hostname can then take every pod.
- The zone item stays `DoNotSchedule`. One labeled zone still schedules every API pod of the live color. metrics-server zone spread and Cluster Autoscaler zone spread stay `DoNotSchedule`.
- The kube-proxy managed addon schema still rejects `tolerations`. Coverage between applies depends on the [0097](0097-kube-proxy-toleration-hook.md) hook and on the flag being true.
- Dropping `DoNotSchedule` on the hostname item, setting `minDomains`, ignoring node affinity or taints, adding required hostname anti-affinity, or softening the zone item fails `check-api-hostname-hard-spread.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.
