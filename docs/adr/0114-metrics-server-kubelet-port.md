- **Date:** 2026-09-23
- **Code:** `deploy/k8s/metrics-server-kubelet-port.sh`; `deploy/k8s/check-metrics-server-kubelet-port.sh`

## Decision

**`apply` writes ConfigMap `metrics-server-kubelet-ca` from `ca.crt` only after every supplied node file set has a non-zero `kubeletEndpoint.port` equal to the kubelet listen port, and the SAN verify from [0113](0113-metrics-server-kubelet-san.md) has passed. metrics-server v0.9.0 dials that status port when it is non-zero, otherwise port 10250. A missing port, a zero, a port that is not the listen port, a manifest that drops `--kubelet-use-node-status-port`, a manifest that sets `--kubelet-port`, or `--kubelet-insecure-tls` refuses apply before `kubectl`. Kind and minikube are refused. The script does not connect to a node. The certificates stay out of git. No live AWS apply.**

1. **The dial rule stays the v0.9.0 rule.** With `--kubelet-use-node-status-port` set, `GetMetrics` uses `status.daemonEndpoints.kubeletEndpoint.port` when that integer is non-zero. Otherwise it uses `--kubelet-port`, whose default in `NewKubeletClientOptions` is 10250. The manifest keeps the bare flag once and does not set `--kubelet-port`, so the fallback stays 10250. `--secure-port=10250` is the addon's serving port. It is not the kubelet dial port. This slice does not change either flag.
2. **The node file set.** Each `nodes/<name>/` directory gains `kubelet-port`. `status` is `status.daemonEndpoints.kubeletEndpoint.port`. `listen` is the kubelet secure listen port (`KubeletConfiguration.port`). Other lines are refused. A value is a decimal integer from 0 through 65535 with no leading zero. The kubelet private key is not required and is not written into the ConfigMap.
3. **The compare.** The dial port is the status value when it is non-zero, otherwise 10250. A missing `status` refuses. A recorded kubeletEndpoint.port is zero when the status value is 0, and that file is refused: that zero is not the dial port, and this gate does not treat the 10250 fallback as a recorded endpoint. A missing `listen` refuses. A zero `listen` refuses. A non-zero status that is not the listen port refuses, because that is the port metrics-server will dial. A non-default pair such as 10255 and 10255 is accepted. The second node is checked the same way. One wrong node refuses the directory.
4. **One apply writes the ConfigMap.** `apply` calls `verify` before any `kubectl`. `verify` checks the port file, then calls `metrics-server-kubelet-san.sh verify`. It then creates ConfigMap `metrics-server-kubelet-ca` in `kube-system` from that same `ca.crt`. It does not apply `metrics-server.yaml`, does not write Secret `metrics-server-serving`, and does not patch APIService `caBundle`. The manifest still does not contain a PEM. `metrics-server-kubelet-ca.sh` remains the chain-only writer. `metrics-server-kubelet-san.sh` remains the address-only writer. Neither of those reads `kubelet-port`.
5. **The gate.** `COMPUTERPETS_METRICS_KUBELET_PORT_APPLY` must be `1`. Without it, `apply` exits and does not call `kubectl`. A current context of kind or minikube, or an empty context, exits before the ConfigMap. `verify` never calls `kubectl`. `verify` and `apply` refuse a directory inside this repo. Neither command connects to a node. There is no dial flag. A manifest whose body sets `--kubelet-insecure-tls`, drops the bare status-port flag, sets `--kubelet-port`, drops the CA flag, or mounts both a ConfigMap and a Secret of that name refuses before `kubectl`.
6. **What stays.** `--kubelet-insecure-tls` stays unset. `insecureSkipTLSVerify` stays unset. `--kubelet-use-node-status-port` stays the bare flag. `--kubelet-port` stays unset. The serving-cert path stays [0111](0111-metrics-server-serving-cert-chain.md). The chain gate stays [0112](0112-metrics-server-kubelet-ca-chain.md). The SAN gate stays [0113](0113-metrics-server-kubelet-san.md). The file stays out of the kustomization. Kind and minikube do not apply it.
7. **Verify without a cluster.** `check-metrics-server-kubelet-port.sh` builds leaves outside the repo. It accepts status 10250 when listen is 10250, and a non-default pair when both sides match. It refuses a missing `kubelet-port` file, a missing status, a missing listen port, a zero status beside listen 10250, a status that is not the listen port, a listen port that is not the dial port, a port above 65535, a leading zero, a duplicated status, a missing node file set, and one bad node beside a good one. It refuses a SAN miss after the port matches, so this apply cannot skip [0113](0113-metrics-server-kubelet-san.md). It refuses `apply` with no opt-in, on kind, and on minikube, and it refuses a port miss before a stub `kubectl` is invoked. A stubbed opt-in apply must show ConfigMap `metrics-server-kubelet-ca` created from that `ca.crt`, and must not show `metrics-server.yaml`, `caBundle`, or a node connection. `check-metrics-server-kubelet-port.test.sh` proves a skipped compare, a skipped zero check, a skipped SAN call, a skipped `verify`, a dropped kind/minikube refusal, a dropped opt-in, `--kubelet-insecure-tls`, a dropped status-port flag, an added `--kubelet-port`, and a kustomize listing. No `kubectl apply` against a cluster and no `terraform apply`.

## Consequences

- A keeper who places the kubelet serving CA and one directory per node (`kubelet.crt`, `addresses`, and `kubelet-port`) outside the repo, then runs `apply` with the opt-in, gives both metrics-server pods a trust anchor whose leaves cover the dial address and whose recorded port is the port those scrapes dial. `kubectl top` can use that scrape when the live node status port and the live listen port are the ones in the file. The pods can still be Running when the file is wrong; this gate stops the port miss before `kubectl`.
- A missing `kubelet-port`, a zero `kubeletEndpoint.port`, or a status port that is not the listen port does not get a ConfigMap from this script. A SAN miss does not get one either.
- Kind and minikube do not receive this ConfigMap. The manifest stays out of `kubectl apply -k deploy/k8s`.
- The script does not connect to a node. A file set that names a listen port the live kubelet does not use still passes. A node omitted from `nodes/` is not checked. `metrics-server-kubelet-ca.sh apply` and `metrics-server-kubelet-san.sh apply` still write the ConfigMap without reading `kubelet-port`. That residual stays locked. It is not the next slice.
- The kubelet private key is not an input. The CA private key is not an input. Neither is written into the ConfigMap or into git.
- Adding `--kubelet-insecure-tls`, adding `--kubelet-port`, dropping `--kubelet-use-node-status-port`, skipping the port compare, skipping the zero check, skipping the SAN verify, or skipping `verify` before `kubectl` fails `check-metrics-server-kubelet-port.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.
- **Next gap:** Mac / Linux window play (`mac-linux-window-play`). The overlay enumerates windows on Windows 10/11. That door does not play a window on Mac or Linux, and it is not faked. This port gate is the last metrics-server TLS/dial slice. Do not start another metrics-server TLS or dial slice for a file that lies or for a writer that still ignores the port. Do not set `--kubelet-insecure-tls`. Do not set `minDomains`. Do not start Pane. Do not start DirectX 12, Vulkan, or Solana. Catalog stays 221.
