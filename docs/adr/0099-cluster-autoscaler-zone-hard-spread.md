# 0099. Hard zone spread for Cluster Autoscaler

- **Status:** Accepted (the running leader's scale path for a Pending standby is [0101](0101-cluster-autoscaler-leader-scale.md); this zone item stays)
- **Date:** 2026-09-23
- **Code:** `deploy/k8s/cluster-autoscaler.yaml`; `deploy/k8s/check-cluster-autoscaler-zone-hard-spread.sh`

A preferred anti-affinity scores a different zone and still binds when the score cannot be met. On a pool that already has two labeled zones, that still allows 2 and 0. Required zone anti-affinity is the wrong lever: it skips the second pod whenever every node shares one zone, including after a zone loss that leaves one domain, and it skips nodes that omit the label. `minDomains: 2` is also the wrong lever: with one eligible domain it treats the global minimum as 0, so the second pod's skew is 2 and the pod stays Pending. Kind and minikube would then fail even after a human sets one zone label. The API colors and metrics-server already use `DoNotSchedule` without `minDomains`. This Deployment follows that shape. The preferred zone term is the same fact as the spread, so it is not kept beside it. There is one zone rule.

## Decision

**The zone placement for Cluster Autoscaler is one `topologySpreadConstraints` item with `whenUnsatisfiable: DoNotSchedule`. `maxSkew` is 1. `nodeAffinityPolicy` is `Honor`. `nodeTaintsPolicy` is `Honor`. `minDomains` stays unset. The preferred zone anti-affinity term is removed. Required hostname anti-affinity stays. Replicas stay 2. The pool selector, the `NoSchedule` toleration, leader election, and `minAvailable: 1` stay. One labeled zone still schedules both pods when two hostnames exist. A node that omits `topology.kubernetes.io/zone` does not. Kind and minikube do not apply this file. Required zone anti-affinity is not set.**

1. **Zone item.** One item. `topologyKey` is `topology.kubernetes.io/zone`. `maxSkew: 1`. `whenUnsatisfiable: DoNotSchedule`. `nodeTaintsPolicy: Honor`. `nodeAffinityPolicy: Honor`. `labelSelector.matchLabels` is `app: cluster-autoscaler`. The pods run in `kube-system`. API pods and metrics-server pods do not count toward this skew. `matchLabelKeys` is not set. There is no second zone item and no preferred zone anti-affinity term.
2. **No minDomains.** Unset minDomains behaves as 1. Do not set minDomains. A floor of 2 would treat a single labeled zone as an empty second domain and leave the second pod Pending. That is the laptop failure this slice refuses.
3. **What hard spread does.** Eligible domains are zones of nodes that match the pool selector, that this pod can tolerate, and that carry `topology.kubernetes.io/zone`. The skew is the count in the candidate zone, plus one, minus the smallest count among those domains. `maxSkew: 1` refuses a larger difference. On two or more such zones that can take a pod, the two replicas cannot share one zone. The placement is 1 and 1, not 2 and 0. If the lighter zone has no remaining capacity, the second pod stays Pending.
4. **One labeled zone still schedules.** When every eligible node shares one zone value, there is one domain. The skew of adding a pod there is 1, which `maxSkew: 1` allows. Hard spread does not invent a second zone. Both replicas schedule when two hostnames exist. Required hostname anti-affinity still leaves the second pod Pending on one node. That Pending pod is [0090](0090-cluster-autoscaler-ha.md), not this zone item. A zone outage that removes the other zone's nodes leaves one domain, and the remaining zone can take both pods when two hostnames remain.
5. **Missing zone label.** `DoNotSchedule` skips a node that does not have `topology.kubernetes.io/zone`. A pool label alone leaves both pods Pending.
6. **Kind and minikube.** This file stays out of the kustomization. `kubectl apply -k deploy/k8s` does not install it. Kind and minikube do not apply it. `enable_node_pool=false` does not label their nodes and does not set a zone. A keeper who applies the file there leaves both pods Pending until a node carries `computerpets/node-pool=api` and one `topology.kubernetes.io/zone` value, and the second pod still waits for a second hostname. One labeled zone still schedules. Do not set `minDomains`. Do not add required zone anti-affinity. Do not taint a kind or minikube node. A toleration does not require the taint. Do not delete the pool key to make a laptop apply schedule.
7. **Hostname anti-affinity stays required.** `podAntiAffinity.requiredDuringSchedulingIgnoredDuringExecution` stays on `kubernetes.io/hostname`. It is not rewritten into a preference. It is not given a second required term on `topology.kubernetes.io/zone`. A required zone term would leave the second pod Pending in one zone. Two hostnames in one zone still satisfy the hostname rule. The preferred zone term from [0090](0090-cluster-autoscaler-ha.md) is not kept: the spread is the zone rule.
8. **What this slice does not change.** `replicas: 2` stays. The file is not in the kustomization. Rolling update `maxUnavailable` stays 1 and `maxSurge` stays 0. Leader election stays `--leader-elect=true` on the `leases` lock named `cluster-autoscaler`. The `PodDisruptionBudget` stays `minAvailable: 1`. The pool selector and the taint toleration stay. The image stays `registry.k8s.io/autoscaling/cluster-autoscaler:v1.36.1`. HPA stays min 3 / max 10. The API PDB stays `minAvailable: 2`. The API zone item stays `DoNotSchedule`. The metrics-server zone item stays `DoNotSchedule`. The kube-proxy reassert hook stays [0097](0097-kube-proxy-toleration-hook.md). No live AWS apply.
9. **Verify without a cluster.** `check-cluster-autoscaler-zone-hard-spread.sh` fails when the zone item is not `DoNotSchedule`, when `maxSkew` is not 1, when `nodeAffinityPolicy` or `nodeTaintsPolicy` is not `Honor`, when `minDomains` or `matchLabelKeys` is set, when a preferred zone term returns, when replicas are not 2, when hostname anti-affinity is no longer required, when a required zone anti-affinity term appears, when the pool selector or the taint toleration drops, when leader election is off, when `minAvailable` is not 1, when `kustomization.yaml` lists the file, or when the API or metrics-server zone item is no longer `DoNotSchedule`. `check-cluster-autoscaler-zone-hard-spread.test.sh` proves a soft zone item, `minDomains: 2`, `nodeAffinityPolicy: Ignore`, a dropped taint policy, `maxSkew: 2`, one replica, a removed hostname rule, a required zone term, a restored preferred zone term, a dropped pool key, a dropped toleration, leader election turned off, `minAvailable: 2`, a kustomize listing, and a soft metrics-server zone item. No `kubectl apply` and no `terraform apply`.

## Consequences

- On a pool whose nodes span two or more zones and can take a pod, the two Cluster Autoscaler replicas cannot share one zone. `maxSkew: 1` and `DoNotSchedule` refuse the crowded zone.
- One labeled zone still schedules both pods when two hostnames exist. Hard spread is not a second zone. A one-node cluster still leaves the second pod Pending on the hostname rule.
- Kind and minikube do not apply this file. Applying it there without `computerpets/node-pool=api` leaves both pods Pending. Applying it with that label and without `topology.kubernetes.io/zone` also leaves both pods Pending. Set one zone value. Do not set `minDomains`. Do not add required zone anti-affinity. Do not taint a kind or minikube node.
- When the lighter zone cannot fit the second pod, it stays Pending instead of joining the crowded zone. That pod is not leading, so it does not call `SetDesiredCapacity` for the group that would fit it. The replica that is already scheduled still can. That stall is the cost of hard-spreading the scaler.
- A zone that loses every eligible node stops being a domain. The remaining zone can then take both pods when two hostnames remain. The budget does not apply to that crash. Required zone anti-affinity would have left the second pod Pending in that remaining zone. It is not set.
- Required hostname anti-affinity stays. The two pods still cannot share a node. Leader election stays on. `minAvailable` stays 1.
- The API zone item stays `DoNotSchedule`. The metrics-server zone item stays `DoNotSchedule`. One labeled zone still schedules every API pod of the live color, and both metrics-server pods when two hostnames exist.
- The kube-proxy managed addon schema still rejects `tolerations`. Coverage between applies depends on the [0097](0097-kube-proxy-toleration-hook.md) hook and on the flag being true.
- Dropping `DoNotSchedule` on the zone item, setting `minDomains`, ignoring node affinity or taints, restoring a preferred zone term, dropping required hostname anti-affinity, or adding a required zone term fails `check-cluster-autoscaler-zone-hard-spread.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.

Required zone anti-affinity is not the follow-up.
