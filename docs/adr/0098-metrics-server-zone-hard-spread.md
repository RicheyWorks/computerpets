# 0098. Hard zone spread for metrics-server

- **Status:** Accepted
- **Date:** 2026-09-23
- **Code:** `deploy/k8s/metrics-server.yaml`; `deploy/k8s/check-metrics-server-zone-hard-spread.sh`

## Context

[0097](0097-kube-proxy-toleration-hook.md) left this gap: metrics-server zone spread stays `ScheduleAnyway`, so both replicas can still land in one labeled zone. Inventory on `main` tip `6976ab61f`:

| Surface | What it did | What it did not do |
|---------|-------------|--------------------|
| `deploy/k8s/metrics-server.yaml` zone item | `topology.kubernetes.io/zone`, `maxSkew: 1`, `whenUnsatisfiable: ScheduleAnyway`, `nodeTaintsPolicy: Honor`, `nodeAffinityPolicy: Honor`, selector `k8s-app=metrics-server` | A preference. Both pods can still land in one labeled zone |
| Hostname anti-affinity | Required on `kubernetes.io/hostname` for `k8s-app: metrics-server` in `kube-system`. `replicas: 2` | Not a zone rule. Two hostnames in one zone satisfy it |
| Pool pin and taint | `nodeSelector` is `kubernetes.io/os: linux` and `computerpets/node-pool: api`. Toleration `computerpets/node-pool=api:NoSchedule` ([0089](0089-metrics-server-node-pool.md), [0094](0094-api-pool-taint.md)) | Unchanged by this slice |
| Kustomization | The file is omitted | Kind and minikube do not apply it |
| API colors ([0095](0095-api-zone-hard-spread.md)) | Zone item is already `DoNotSchedule` | Not this Deployment |
| `deploy/k8s/cluster-autoscaler.yaml` | Preferred pod anti-affinity on `topology.kubernetes.io/zone`, weight 100. Required anti-affinity is hostname only | Required zone anti-affinity is not the follow-up |
| `deploy/terraform/modules/node_pool/main.tf` | At least two availability zones. EKS sets `topology.kubernetes.io/zone` from the instance AZ | This slice does not change the module |

`ScheduleAnyway` scores a less-loaded zone and still binds when the score cannot be met. On a pool that already has two labeled zones, that still allows 2 and 0. `minDomains: 2` is the wrong lever: with one eligible domain it treats the global minimum as 0, so the second pod's skew is 2 and the pod stays Pending. Kind and minikube would then fail even after a human sets one zone label. Required zone anti-affinity is also the wrong lever: it skips the second pod whenever every node shares one zone. The API colors already use `DoNotSchedule` without `minDomains` ([0095](0095-api-zone-hard-spread.md)). This addon follows that shape.

This slice does not reopen presence/CSP, Hikari/replica pool sizing, bundle zip, cosign, CDN edge, secrets rotation, VerifyFieldBounds, ClientAddress, rate-limit bucket sizes, the machine/admin HMAC, the nonce store, the download JWT `jti`, the WAF ACL, Redis AUTH, Postgres JDBC SSL, API listener TLS, the HPA metrics and replica range, the API PDB `minAvailable`, the API hostname spread, the API zone `DoNotSchedule` item, the node-pool pin or taint, Cluster Autoscaler replica count, anti-affinity, leader election, node-pool pin, and disruption budget, aws-node, vpc-cni, or the kube-proxy reassert hook beyond this cross-link. Required zone anti-affinity for Cluster Autoscaler stays unset. Catalog stays 221. No storefront. No DirectX 12 / Vulkan / Solana. No Rui sprites.

## Decision

**The zone `topologySpreadConstraints` item on metrics-server sets `whenUnsatisfiable: DoNotSchedule`. `maxSkew` stays 1. `nodeAffinityPolicy` stays `Honor`. `nodeTaintsPolicy` stays `Honor`. `minDomains` stays unset. Required hostname anti-affinity stays. Replicas stay 2. The pool selector and the `NoSchedule` toleration stay. One labeled zone still schedules both pods when two hostnames exist. A node that omits `topology.kubernetes.io/zone` does not. Kind and minikube do not apply this file.**

1. **Zone item.** One item. `topologyKey` is `topology.kubernetes.io/zone`. `maxSkew: 1`. `whenUnsatisfiable: DoNotSchedule`. `nodeTaintsPolicy: Honor`. `nodeAffinityPolicy: Honor`. `labelSelector.matchLabels` stays `k8s-app: metrics-server`. The pods run in `kube-system`. API pods do not count toward this skew. `matchLabelKeys` is not set.
2. **No minDomains.** Unset minDomains behaves as 1. Do not set minDomains. A floor of 2 would treat a single labeled zone as an empty second domain and leave the second pod Pending. That is the laptop failure this slice refuses.
3. **What hard spread does.** Eligible domains are zones of nodes that match the pool selector, that this pod can tolerate, and that carry `topology.kubernetes.io/zone`. The skew is the count in the candidate zone, plus one, minus the smallest count among those domains. `maxSkew: 1` refuses a larger difference. On two or more such zones that can take a pod, the two replicas cannot share one zone. The placement is 1 and 1, not 2 and 0. If the lighter zone has no remaining capacity, the second pod stays Pending. Cluster Autoscaler can add a node in that zone. This slice does not change the scaler.
4. **One labeled zone still schedules.** When every eligible node shares one zone value, there is one domain. The skew of adding a pod there is 1, which `maxSkew: 1` allows. Hard spread does not invent a second zone. Both replicas schedule when two hostnames exist. Required hostname anti-affinity still leaves the second pod Pending on one node. That Pending pod is [0085](0085-metrics-server-ha.md), not this zone item. A zone outage that removes the other zone's nodes leaves one domain, and the remaining zone can take both pods when two hostnames remain.
5. **Missing zone label.** `DoNotSchedule` skips a node that does not have `topology.kubernetes.io/zone`. `ScheduleAnyway` used to bind on that node. It does not anymore. A pool label alone leaves both pods Pending.
6. **Kind and minikube.** This file stays out of the kustomization. `kubectl apply -k deploy/k8s` does not install it. Kind and minikube do not apply it. `enable_node_pool=false` does not label their nodes and does not set a zone. A keeper who applies the file there leaves both pods Pending until a node carries `computerpets/node-pool=api` and one `topology.kubernetes.io/zone` value, and the second pod still waits for a second hostname. One labeled zone still schedules. Do not set `minDomains`. Do not taint a kind or minikube node. A toleration does not require the taint. Do not delete the pool key to make a laptop apply schedule.
7. **Hostname anti-affinity stays required.** `podAntiAffinity.requiredDuringSchedulingIgnoredDuringExecution` stays on `kubernetes.io/hostname`. It is not rewritten into a preference. It is not given a second required term on `topology.kubernetes.io/zone`. A required zone term would leave the second pod Pending in one zone. Two hostnames in one zone still satisfy the hostname rule.
8. **What this slice does not change.** `replicas: 2` stays. The file is not in the kustomization. Rolling update `maxUnavailable` stays 1. The addon `PodDisruptionBudget` stays `minAvailable: 1`. The kubelet CA mount and the serving Secret stay. `insecureSkipTLSVerify` stays unset. `--kubelet-insecure-tls` stays unset. The image stays `registry.k8s.io/metrics-server/metrics-server:v0.9.0`. The pool selector and the taint toleration stay. HPA stays min 3 / max 10. The API PDB stays `minAvailable: 2`. The API zone item stays `DoNotSchedule`. Cluster Autoscaler zone spread is [0099](0099-cluster-autoscaler-zone-hard-spread.md). Required zone anti-affinity is not the follow-up. The kube-proxy reassert hook stays [0097](0097-kube-proxy-toleration-hook.md). No live AWS apply.
9. **Verify without a cluster.** `check-metrics-server-zone-hard-spread.sh` fails when the zone item is not `DoNotSchedule`, when `maxSkew` is not 1, when `nodeAffinityPolicy` or `nodeTaintsPolicy` is not `Honor`, when `minDomains` or `matchLabelKeys` is set, when replicas are not 2, when hostname anti-affinity is no longer required, when a required zone anti-affinity term appears, when the pool selector or the taint toleration drops, when `kustomization.yaml` lists the file, or when Cluster Autoscaler zone anti-affinity becomes required. `check-metrics-server-zone-hard-spread.test.sh` proves a soft zone item, `minDomains: 2`, `nodeAffinityPolicy: Ignore`, a dropped taint policy, `maxSkew: 2`, one replica, a removed hostname rule, a required zone term, a dropped pool key, a dropped toleration, a kustomize listing, and a required scaler zone rule. No `kubectl apply` and no `terraform apply`.

## Consequences

- On a pool whose nodes span two or more zones and can take a pod, the two metrics-server replicas cannot share one zone. `maxSkew: 1` and `DoNotSchedule` refuse the crowded zone.
- One labeled zone still schedules both pods when two hostnames exist. Hard spread is not a second zone. A one-node cluster still leaves the second pod Pending on the hostname rule.
- Kind and minikube do not apply this file. Applying it there without `computerpets/node-pool=api` leaves both pods Pending. Applying it with that label and without `topology.kubernetes.io/zone` also leaves both pods Pending. Set one zone value. Do not set `minDomains`. Do not taint a kind or minikube node.
- When the lighter zone cannot fit the second pod, it stays Pending instead of joining the crowded zone. That wait is the cost of hard spread. Cluster Autoscaler is what adds the node. This slice does not apply it.
- A zone that loses every eligible node stops being a domain. The remaining zone can then take both pods when two hostnames remain. The addon budget does not apply to that crash.
- Required hostname anti-affinity stays. The two pods still cannot share a node.
- Cluster Autoscaler zone spread is [0099](0099-cluster-autoscaler-zone-hard-spread.md). Required zone anti-affinity is not the follow-up. The API zone item stays `DoNotSchedule`. One labeled zone still schedules every API pod of the live color.
- The kube-proxy managed addon schema still rejects `tolerations`. Coverage between applies depends on the [0097](0097-kube-proxy-toleration-hook.md) hook and on the flag being true.
- Dropping `DoNotSchedule` on the zone item, setting `minDomains`, ignoring node affinity or taints, dropping required hostname anti-affinity, adding a required zone term, or making the scaler's zone rule required fails `check-metrics-server-zone-hard-spread.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.
- **Next gap:** the kube-proxy managed addon schema still rejects `tolerations`, so coverage between applies depends on the reassert hook and on the flag being true. If the reasserted patch does not stick and Exists is also gone, apply fails closed and the node can stay NotReady. Cluster Autoscaler zone spread is [0099](0099-cluster-autoscaler-zone-hard-spread.md). Required zone anti-affinity is not the follow-up. One labeled zone still schedules both metrics-server pods when two hostnames exist. A node that omits `topology.kubernetes.io/zone` leaves those pods Pending. If the lighter zone cannot fit the second pod, it stays Pending. One labeled zone still schedules every API pod of the live color. The serving certificate chains to APIService `caBundle` and its DNS SAN is `metrics-server.kube-system.svc` ([0111](0111-metrics-server-serving-cert-chain.md)). A kubelet certificate that does not chain to `metrics-server-kubelet-ca` still leaves `kubectl top` empty.
