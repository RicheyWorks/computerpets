# 0110. A Pending Cluster Autoscaler pod never holds the lease

- **Status:** Accepted
- **Date:** 2026-09-23
- **Code:** `deploy/k8s/cluster-autoscaler.yaml`; `deploy/k8s/check-cluster-autoscaler-pending-lease.sh`

## Context

[0109](0109-per-zone-node-max-floor.md) left this gap: a Pending Cluster Autoscaler standby still does not hold `leases/cluster-autoscaler`, so nothing raises desired capacity for the group that would fit it. The max of 20 is not why that pod is Pending. Inventory on `main` tip `14cf22547` (cluster-autoscaler v1.36.1 `main.go`; the Deployment, the lease RBAC, and the built-in PriorityClass in this repo):

Preemption, the disruption budget, and the priority class can make a resource-starved replica Running. They cannot make a Pending replica the holder. The holder is the process that called `OnStartedLeading`. When zero replicas are Running, this binary raises nothing. Turning leader election off does not fix that: a Pending process is still absent, and every Running replica would scale.

## Decision

**A Pending Cluster Autoscaler pod never holds `leases/cluster-autoscaler`. The Running leader remains the scaler. v1.36.1 acquires that lease inside the container (`leaderelection.RunOrDie` in `main`, identity `os.Hostname()`, `OnStartedLeading` starts the scale loop). No flag, PriorityClass, or disruption budget writes the Lease for a container that has not started. `priorityClassName` stays `system-cluster-critical`, so a lower-priority pod can be preempted and this replica can become Running and then take the lease. It cannot preempt a missing hostname. When zero replicas are Running, nothing in this binary raises desired capacity. Kind and minikube do not apply the file. No live AWS apply.**

1. **Who holds the lease.** `replicas` stay 2. `--leader-elect=true` stays, on the `leases` lock named `cluster-autoscaler`, in `--namespace=kube-system`. The identity is the hostname of the running container. Only `OnStartedLeading` starts the scale loop. A Pending pod does not call it. `--leader-elect=false` is refused: it does not start a Pending container, and it would let every Running replica scale. Lease duration, renew deadline, and retry period stay at the v1.36.1 defaults (`15s`, `10s`, `2s`), unset on the command. Setting them is refused. They change how fast a Running candidate retries. `--leader-elect-resource-namespace` is refused. This binary does not pass that flag into `resourcelock.New`.
2. **What can make the replica Running.** `priorityClassName` stays `system-cluster-critical`. API pods have no class and can be preempted. `system-node-critical` is refused. A custom PriorityClass is refused. `preemptionPolicy: Never` is refused. metrics-server stays on the same built-in class and is not a victim of this slice. The class does not satisfy required hostname anti-affinity and does not satisfy the zone item.
3. **What keeps the Running leader.** The disruption budget stays `minAvailable: 1` on `app=cluster-autoscaler` ([0092](0092-cluster-autoscaler-pdb.md)). One Ready replica and one Pending replica allow zero voluntary evictions. `minAvailable: 0` is refused. `minAvailable: 2` is refused. There is one container, named `cluster-autoscaler`, image `registry.k8s.io/autoscaling/cluster-autoscaler:v1.36.1`. An init container or a second container is refused. Neither starts while the pod is Pending, so neither can hold the lease in the pod's place. `cluster-autoscaler.kubernetes.io/safe-to-evict` stays unset.
4. **What stays the scaler.** The Running holder keeps `--balance-similar-node-groups=true`, `--expander=least-waste`, `--skip-nodes-with-system-pods=false`, `--salvo-scale-up=true`, `--salvo-scale-up-budget=1m`, and `--frequent-loops-enabled=true`. The standby is not the scaler. The zone item, the required hostname anti-affinity, the pool pin, and the taint toleration stay. `minDomains` stays unset. Do not set minDomains. Required zone anti-affinity is not set. `max_size` stays 20 ([0109](0109-per-zone-node-max-floor.md)). This slice does not apply a group.
5. **The residual.** When zero replicas are Running, nothing in this binary calls `SetDesiredCapacity`. The node group `min_size` is what keeps the floor nodes. A desired size that is still 1, or still 2, is still a keeper bump ([0106](0106-api-single-zone-hostname-floor.md)). This file does not pretend a Pending pod will grow that group.
6. **Kind and minikube.** This file stays out of the kustomization. `kubectl apply -k deploy/k8s` does not install it. Kind and minikube do not apply this file. Do not add it to make a laptop scale. Do not set `minDomains`. Do not taint a kind or minikube node.
7. **Verify without a cluster.** `check-cluster-autoscaler-pending-lease.sh` fails when leader election is off or the lock is not `leases` / `cluster-autoscaler`, when a lease-duration, renew, retry, or resource-namespace flag is set, when `priorityClassName` is missing or not `system-cluster-critical`, when a custom PriorityClass or `preemptionPolicy: Never` appears, when `minAvailable` is not 1, when an init container or a second container appears, when `safe-to-evict` is set, when the image is not v1.36.1, when replicas are not 2, when `minDomains` is set, when required zone anti-affinity appears, when the lease RBAC drops `create` or the named `get`/`update`, or when `kustomization.yaml` lists the file. `check-cluster-autoscaler-pending-lease.test.sh` proves those regressions. No `kubectl apply` and no `terraform apply`.

## Consequences

- A Pending Cluster Autoscaler pod never holds `leases/cluster-autoscaler`. The Running leader remains the scaler, including for the Auto Scaling group that would fit that Pending pod.
- `system-cluster-critical` still lets this pod preempt a priority-0 pod and become Running. After it is Running it can take the lease. The same class does not place it on a hostname that required anti-affinity forbids, and it does not invent a zone.
- A voluntary drain cannot remove the only Ready replica while the other is Pending. A node crash is not a voluntary disruption. The crashed replica's lease expires on the `15s` default. The other replica takes it only if that other replica is already Running.
- When zero replicas are Running, desired capacity stays where the Auto Scaling group already put it. This binary does not raise it from a Pending pod.
- Kind and minikube do not apply this file. One labeled zone still schedules both pods when two hostnames exist. Do not set `minDomains`. Required zone anti-affinity is not set.
- Turning leader election off, shortening the lease clocks, switching the lock, dropping or raising the priority class, or adding a container that is supposed to hold the lease while the pod is Pending fails `check-cluster-autoscaler-pending-lease.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.
- **Next gap:** a serving certificate that does not chain to `caBundle` (and is not a system root), or whose SAN is not `metrics-server.kube-system.svc`, still leaves `kubectl top` empty ([0087](0087-metrics-server-serving-cert.md)). That is outside this Cluster Autoscaler loop. A kubelet certificate that does not chain to `metrics-server-kubelet-ca` still leaves `kubectl top` empty ([0086](0086-metrics-server-kubelet-ca.md)). Do not set `minDomains`. Required hostname anti-affinity is not the follow-up. Required zone anti-affinity is not the follow-up. The kube-proxy managed addon schema still rejects `tolerations`, so coverage between applies depends on the [0097](0097-kube-proxy-toleration-hook.md) hook and on the flag being true. One labeled zone still schedules both metrics-server pods when two hostnames exist. If the lighter zone cannot fit the second metrics-server pod, it stays Pending. One hostname still schedules every API pod of the live color.
