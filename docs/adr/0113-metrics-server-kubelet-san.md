## Decision

**`apply` writes ConfigMap `metrics-server-kubelet-ca` from `ca.crt` only after every supplied node file set chains to that CA and the leaf SAN covers the dial address. The dial address is the first `InternalIP`, else the first `ExternalIP`, else the first `Hostname`, in the order those lines appear in that node's `addresses` file. A missing address, a SAN miss, a leaf that does not chain, a manifest whose dial flag is not that order, or `--kubelet-insecure-tls` refuses apply before `kubectl`. Kind and minikube are refused. The script does not connect to a node. The certificates stay out of git. No live AWS apply.**

1. **The dial order stays on the manifest.** The container arg stays `--kubelet-preferred-address-types=InternalIP,ExternalIP,Hostname`, once. That is the order `prioNodeAddrResolver` walks. The first `status.addresses` entry of the first present type is the URL host. Later types are not tried when TLS fails. This slice does not reorder the flag and does not add `InternalDNS` or `ExternalDNS`.
2. **The node file set.** `ca.crt` is one CA (`CA:TRUE`). Each `nodes/<name>/` directory is one node. `kubelet.crt` is one end entity whose issuer is that CA. `openssl verify -CAfile ca.crt kubelet.crt` must succeed. `addresses` lists `InternalIP`, `ExternalIP`, and `Hostname` lines in `status.addresses` order. Other types are refused. The first line of the winning type is the dial address. An `InternalIP` or `ExternalIP` value must be an IP. The kubelet private key is not required and is not written into the ConfigMap.
3. **The SAN.** An IP dial address must equal an IP SAN. A hostname dial address must equal a DNS SAN, or a DNS wildcard whose leftmost label is `*` and which matches one label. Comparison of DNS names ignores ASCII case and a trailing dot. A DNS name does not cover an IP dial. An IP SAN does not cover a hostname dial. A leaf with no SAN does not cover a dial address. The second `InternalIP` does not cover a dial of the first `InternalIP`.
4. **One apply writes the ConfigMap.** `apply` calls `verify` before any `kubectl`. It then creates ConfigMap `metrics-server-kubelet-ca` in `kube-system` from that same `ca.crt`. It does not apply `metrics-server.yaml`, does not write Secret `metrics-server-serving`, and does not patch APIService `caBundle`. The manifest still does not contain a PEM. `metrics-server-kubelet-ca.sh` remains the chain-only writer and still does not read this file set.
5. **The gate.** `COMPUTERPETS_METRICS_KUBELET_SAN_APPLY` must be `1`. Without it, `apply` exits and does not call `kubectl`. A current context of kind or minikube, or an empty context, exits before the ConfigMap. `verify` never calls `kubectl`. `verify` and `apply` refuse a directory inside this repo. Neither command connects to a node. There is no dial flag. A manifest whose body sets `--kubelet-insecure-tls`, drops the CA flag, changes the dial order, or mounts both a ConfigMap and a Secret of that name refuses before `kubectl`.
6. **What stays.** `--kubelet-insecure-tls` stays unset. `insecureSkipTLSVerify` stays unset. `--kubelet-use-node-status-port` stays set. The serving-cert path stays [0111](0111-metrics-server-serving-cert-chain.md). The chain gate stays [0112](0112-metrics-server-kubelet-ca-chain.md). The file stays out of the kustomization. Kind and minikube do not apply it.
7. **Verify without a cluster.** `check-metrics-server-kubelet-san.sh` builds leaves outside the repo. It accepts an `InternalIP` that is an IP SAN, an `ExternalIP` used only when `InternalIP` is absent, a `Hostname` DNS SAN, a one-label wildcard, and a case-insensitive DNS name. It refuses a DNS SAN when `InternalIP` is present, a SAN that covers only the second `InternalIP`, a missing node file set, a missing address, an address type outside the dial order, a swapped CA, and one bad node beside a good one. It refuses `apply` with no opt-in, on kind, and on minikube, and it refuses a SAN miss before a stub `kubectl` is invoked. A stubbed opt-in apply must show ConfigMap `metrics-server-kubelet-ca` created from that `ca.crt`, and must not show `metrics-server.yaml`, `caBundle`, or a node connection. `check-metrics-server-kubelet-san.test.sh` proves a skipped SAN check, a reordered dial tuple, a skipped `verify`, a dropped kind/minikube refusal, a dropped opt-in, `--kubelet-insecure-tls`, a reordered manifest flag, a dropped CA flag, and a kustomize listing. No `kubectl apply` against a cluster and no `terraform apply`.

## Consequences

- A keeper who places the kubelet serving CA and one directory per node (`kubelet.crt` plus `addresses` in `status.addresses` order) outside the repo, then runs `apply` with the opt-in, gives both metrics-server pods a trust anchor whose leaves cover the address those scrapes dial. `kubectl top` can use that scrape when the live node address is the one in the file. The pods can still be Running when the file is wrong; this gate stops the SAN miss before `kubectl`.
- A missing `ca.crt`, a missing node directory, a missing `addresses` file, or a leaf that does not chain does not get a ConfigMap from this script. A SAN does not cover the dial address when the IP or DNS name metrics-server would dial is absent, and that file set does not get a ConfigMap either.
- Kind and minikube do not receive this ConfigMap. The manifest stays out of `kubectl apply -k deploy/k8s`.
- The script does not connect to a node. A file set that names an address the live node does not have still passes. A node omitted from `nodes/` is not checked. `metrics-server-kubelet-ca.sh apply` still writes the ConfigMap without reading addresses.
- The kubelet private key is not an input. The CA private key is not an input. Neither is written into the ConfigMap or into git.
- Adding `--kubelet-insecure-tls`, reordering the dial flag, dropping the CA flag, skipping the SAN check, or skipping `verify` before `kubectl` fails `check-metrics-server-kubelet-san.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.

This SAN apply still does not read the port and does not connect to a node. Do not set `--kubelet-insecure-tls`. This is outside the port gate's listen-port compare. Do not set `minDomains`. One hostname still schedules every API pod of the live color.
