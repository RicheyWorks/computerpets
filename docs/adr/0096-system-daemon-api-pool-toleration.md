# 0096. API pool toleration for aws-node and kube-proxy

- **Status:** Accepted
- **Date:** 2026-09-23
- **Code:** `deploy/terraform/modules/system_daemons/`; `deploy/terraform/check-system-daemons.sh`

## Context

[0095](0095-api-zone-hard-spread.md) left this gap: `aws-node` and `kube-proxy` are not in this repo. A live apply of `computerpets/node-pool=api:NoSchedule` can leave a new node NotReady until those DaemonSets tolerate that key, `Equal`, value `api`, and `NoSchedule`. Inventory on `main` tip `7ba0d9133`:

## Decision

**`aws-node` gets the API pool toleration through the `vpc-cni` addon's `configuration_values`. That document is two tolerations: the chart default `operator: Exists`, then key `computerpets/node-pool`, operator `Equal`, value `api`, effect `NoSchedule`. `kube-proxy` gets the same `Equal` entry from a strategic-merge patch, because the managed addon schema rejects `tolerations`. Kind and minikube do not plan the addon and do not run the patch. Do not taint a kind or minikube node. A toleration does not require the taint.**

1. **vpc-cni.** `aws_eks_addon.vpc_cni` is planned when `enable_node_pool` is true and `eks_cluster_name` is set. `configuration_values` is `vpc-cni-configuration-values.json` and nothing else. `resolve_conflicts_on_create` and `resolve_conflicts_on_update` are `OVERWRITE`, so the document is what a live update writes. `PRESERVE` would keep a live document that omits the entry. `addon_version` is unset. `service_account_role_arn` is unset. No image override and no `nameOverride`. The node group module `depends_on` this module, so the same apply updates the addon before it touches the node group. An existing managed addon is imported as `<cluster>:vpc-cni` before that first apply. This root does not create the cluster. No live AWS apply.
2. **Why Exists stays.** `configuration_values` replaces the tolerations list. The chart default is `operator: Exists`. Repeating it keeps tolerate-all for any other custom taint. The second entry is the exact API pool toleration. `NoExecute` is not set. `PreferNoSchedule` is not set. `tolerationSeconds` is not set.
3. **kube-proxy.** The patch file is `kube-proxy-api-pool-toleration.yaml`. It names DaemonSet `kube-proxy` in `kube-system` and adds one toleration: the same key, `Equal`, value `api`, and `NoSchedule`. It sets no container and no image. The live command is `kubectl patch daemonset kube-proxy -n kube-system --type strategic` with that file, run before `terraform apply`. Strategic merge adds the entry beside tolerations that are already there. It does not replace an `operator: Exists` entry. `configuration_values` on a `kube-proxy` addon is not a resource in this root. Sending that field fails schema validation and does not add the toleration.
4. **Who does not change.** Postgres and Redis stay unpinned and do not tolerate the taint. Blue, green, metrics-server, and Cluster Autoscaler keep the toleration they already have. Hostname spread stays `ScheduleAnyway`. The API zone item stays `DoNotSchedule`. metrics-server zone spread is [0098](0098-metrics-server-zone-hard-spread.md). Cluster Autoscaler zone spread is [0099](0099-cluster-autoscaler-zone-hard-spread.md). Required zone anti-affinity is not the follow-up. HPA stays min 3 / max 10. The API PDB stays `minAvailable: 2`.
5. **Kind and minikube.** `enable_node_pool=false` does not instantiate the module, so it does not plan `aws_eks_addon.vpc_cni` and does not taint a laptop node. The patch is not in the kustomization. `kubectl apply -k deploy/k8s` does not patch `kube-proxy`. Do not run the patch on kind or minikube. Do not taint a kind or minikube node. A toleration does not require the taint.
6. **Fail closed.** `terraform_data.system_daemon_toleration_gate` refuses a plan when the JSON is not those two tolerations or the patch drops the `Equal` entry or names an image. `check-system-daemons.sh` fails on the same drift, on a pinned `addon_version`, on a `kube-proxy` addon `configuration_values`, on a kustomization that lists the patch, and on a node pool that no longer waits for the module. `check-system-daemons.test.sh` proves a dropped `Equal` entry, `NoExecute`, a keyed `Exists`, an extra vpc-cni key, an `Exists` patch, an image line in the patch, a missing `depends_on`, a pinned addon version, a kube-proxy `configuration_values`, and a kustomize listing. No `kubectl` and no `terraform apply`.
7. **Before a live apply.** `aws eks describe-addon` for `vpc-cni`. If `configurationValues` is already set and is not this document, stop. `OVERWRITE` replaces that document. This slice does not run that command.

## Consequences

- On a cluster where the vpc-cni addon is imported and this root is applied, `aws-node` carries `operator: Exists` and the exact API pool toleration. The addon image stays the one EKS selected. This repo does not fork it.
- The node group update in that apply waits on the addon update. A new node from this apply is not created ahead of the vpc-cni document.
- `kube-proxy` gains the exact entry only when the keeper runs the patch. The managed addon controller can revert that patch on a later reconcile. If the live DaemonSet already has `operator: Exists`, the taint is still tolerated after a revert. If it does not, the node can return to NotReady until the patch is applied again. That is the remaining gap. Do not paper over it by sending `configuration_values` the schema rejects.
- A keeper who already set other vpc-cni `configurationValues` loses them on `OVERWRITE` unless they stop and fold those keys into a later reviewed change. This document refuses extra keys.
- Kind and minikube apply neither the addon nor the patch. Do not taint a kind or minikube node. A toleration does not require the taint.
- Cluster Autoscaler zone spread is [0099](0099-cluster-autoscaler-zone-hard-spread.md). Required zone anti-affinity is not the follow-up. metrics-server zone spread is [0098](0098-metrics-server-zone-hard-spread.md). One labeled zone still schedules every API pod of the live color.
- Dropping the `Equal` entry, pinning `addon_version`, sending kube-proxy `configuration_values`, or listing the patch in the kustomization fails `check-system-daemons.sh`.
- Catalog stays 221. No Rui sprites. `_*.py` stay untracked.

Required zone anti-affinity is not the follow-up. metrics-server zone spread is [0098](0098-metrics-server-zone-hard-spread.md). One labeled zone still schedules every API pod of the live color. The serving certificate chains to APIService `caBundle` and its DNS SAN is `metrics-server.kube-system.svc` ([0111](0111-metrics-server-serving-cert-chain.md)). A kubelet certificate that does not chain to `metrics-server-kubelet-ca` still leaves `kubectl top` empty.
